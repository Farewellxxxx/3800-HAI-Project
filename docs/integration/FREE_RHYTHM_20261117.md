# 自由节奏录音与编排验证 · 2026-11-17

> 历史记录：下文记录早期自定义检测器及当时的验证，不代表当前识别效果。用户随后明确要求原样复用队友的整段识别函数，当前方案和验收以 [恢复原版 librosa 识别](LIBROSA_FREE_RHYTHM_20261117.md) 为准。旧版“示例识别 10 拍”的预期已撤回；保留原示例音频以如实展示原版的漏拍。

节奏页接收任意拍手、敲击或口技，直接把原录音上的起音秒数和相对力度呈现为可试听和编辑的打击乐。录音与导入支持最长 30 秒，分析接受 0.5–30 秒、8–96 kHz 的音频。工作台的默认编排速度是 120 BPM。自由节奏事件只记录秒数，不从录音推断 BPM 或拍号。

## 当时的验收步骤（历史）

1. 在仓库运行 `start-input-mrt2.cmd`，打开 [自由节奏](http://127.0.0.1:4197/rhythm.html)。点「载入示例」再点「识别节奏」，或直接录一段。内置 7.15 秒示例应显示 10 个拍点，包含强弱不同的拍点和首尾空白。
2. 选第一个拍点，把起音填成 `0.343` 秒、相对力度填成 `48`，点「保存拍点」。点「听 MIDI」，观察时间线指针。点击「下载 MIDI」和「下载 InputEvent JSON」，两份文件使用同一份已编辑节奏。
3. 展开「用当前节奏生成音乐」，选择「跟随拍点」并点「生成音乐」。可以播放、下载 WAV 和生成记录。再次编辑拍点，上一版的试听和下载链接应清除。「撤销」恢复上一版拍点，可重新生成。

## 数据与兼容

- InputEvent `1.3.0` 以原始录音起点为零。`payload.rhythm` 是当前拍点，`payload.raw_rhythm` 保留原始识别结果。两者使用递增的 `onset_seconds` 和对应的 `accents`。编辑分配新的事件 ID。未知会话时间和未经校准的置信度保留为 `null`。
- 纯 MIDI 使用鼓通道上的 GM 音符 36，力度是 `max(1, round(accent * 127))`。120 BPM 是文件内部编码参考。录音时长包含前后静音，即使最后一个拍点已经结束，MIDI 轨仍延续到录音末尾。
- Harness 登记同一事件，并用 `ADJUST_FEEL` 引用它。跟随模式保留原始拍点时刻。活动会话使用自身速度安排小节边界。完整录音决定编排最少小节数，持续编排以包含原首尾空白的整句为周期。输入事件和纯 MIDI 始终只有原始的一次乐句。
- 旧单小节与 count-in 请求保留。已有 `1.0.0`–`1.2.0` InputEvent 仍可加载。JamState 在含自由节奏时使用 `1.1.0`。参见 `docs/INPUT_EVENT_V1.md` 和 `docs/superpowers/specs/2026-11-17-free-rhythm-design.md`。
- MRT2 的 MIDI 只用于条件输入。25 Hz 的编码合并音高并将打击乐表示为二值帧，会丢失力度与具体鼓种。MRT2 输出是试听，试听不提交 JamState。

## 当时的本地验证（历史）

- 独立 API 样本在 7.15 秒和 12.40 秒中命中 10/10 和 8/8 个标注拍点，最弱拍仍被识别。1.74 秒录音命中唯一拍点，只有背景噪声的 2.27 秒音频得到零拍点。12.40 秒样本请求两小节时，跟随编排扩为七小节，保留最后的 11.980 秒拍点。纯 MIDI 保留 12.40 秒时长。
- 同一 12.40 秒样本通过已安装的 `mrt2_small` 和 JAX 生成 14.000 秒、48 kHz 双声道预览。回执为 `real_magenta_rt`，WAV RMS 为 0.05768，模型生成耗时约 75.12 秒，编排没有提交 JamState。最终代码重启后另以 0.50001 秒录音和 0.500 秒拍点验证修订后的 MIDI 写入路径。MRT2 生成 2.000 秒非静音预览，RMS 0.06441，耗时约 66.49 秒。
- 最终代码用 30 秒事件进行了边界检查。纯 MIDI 和编排 MIDI 均保留接近末尾的 29.999999 秒拍点，解码位置为 29.999979 秒，轨道均在 30.000 秒结束。另一份 7.15 秒稀疏节奏的四小节编排 MIDI 在 8.000 秒结束。
- Edge 实测载入示例后把第一拍改为 0.343 秒、力度 48。播放游标走到 7.150 秒。解析实际下载的 MIDI 和 InputEvent JSON 后确认起音与力度一致，生成记录的 `input_event` 与下载 JSON 一致，计划引用其事件 ID。删除拍点会移除旧生成结果，撤销会恢复拍点。另在 400 CSS 像素宽度查看 12.40 秒导入样本，时间线和编辑字段适应窄屏。
- 最后一次修复先确定整句的输出 MIDI 拍点，再按小节切片。重启 4197 后，原长 2.000001 秒、含 1.950 与 2.000 秒拍点的用例通过 HTTP 验证。纯 MIDI、四秒精确编排 MIDI 和 MRT2 条件 MIDI 均解码到 1.950000 与 1.999979 秒，同音高的音符互不重叠，输入事件仍保留原始秒数。最终代码的真实 MRT2 返回 4.000 秒非静音试听，RMS 0.08019，耗时约 60.63 秒，未提交 JamState。
- 自动验证包括边界修订前的完整 Python 套件 472 项、修订后的定向套件 98 项、最后一次跨小节修复后的定向套件 118 项，以及最终 JavaScript 测试 62 项。`git diff --check` 通过。
- 上述拍点数据来自合成诊断音频。麦克风识别准确率、真实环境噪声和人耳音质仍需用真人录音评估。实现和独立验证由 GPT-6.1 Sol 工作者完成。
