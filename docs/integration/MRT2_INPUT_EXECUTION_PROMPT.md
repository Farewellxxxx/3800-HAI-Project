# JamMate 三路 MRT2 输入交接执行 prompt

在用户自己的 `Farewellxxxx/3800-HAI-Project` 本地仓库中，以 `origin/main` 为基线创建新分支。复核独立副本 `JamMate-mrt2-inputs` 中的草稿，只移植哼唱、拍手、文字三路输入导出的改动。交付边界为可重放的输入材料，模型调用留给下一位同学。提交代码、测试、执行 prompt 和交接说明到本地新分支，远程发布另行确认。

1. 哼唱复用当前选中识别结果的旋律 MIDI。输入包解码后的字节必须与页面「下载 MIDI」一致。钢琴卷帘和试听继续用于检查识别结果。
2. 拍手一次识别后可切换「仅识别拍点」和「已生成的整段伴奏」。仅拍点使用一小节标准鼓轨并保留速度、拍点和重音，识别完成即可导出。伴奏使用原版生成结果，换录音、重新识别或修改编排方式、力度、小节数后，须重新生成才能导出伴奏。提供所选 MIDI 和 MRT2 输入包两种下载。
3. 文字从现有输入框原样导出，保留空格、标点和换行。只有空白时禁用导出。现有文字 Agent 流程继续使用。
4. 三路共用 JSON 字段 `schema_version`、`source`、`prompt`、`midi_base64` 和 `duration_s`。文字只提供原文。MIDI 路径提供标准 MIDI 和已知片段时长。接入端负责默认风格和文字路径的生成时长。
5. 在 [交接说明](MRT2_INPUT_HANDOFF.md) 记录操作、验收结果和 Mermaid 流程图，给出文字与 MIDI 两个调用示例。引用团队分支上已经存在的 MRT2 封装，说明文字编码与 MIDI 条件转换由该封装完成。
6. 回读鼓轨，核对拍点和速度。用浏览器实测 MIDI 来源切换、旧伴奏失效、哼唱 MIDI 字节一致、文字原样导出，以及原有伴奏和文字 Agent。运行相关测试及前端构建，交付本地分支名、提交号和文档路径。
