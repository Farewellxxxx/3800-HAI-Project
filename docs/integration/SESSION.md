# 连续会话工作台

入口：双击项目根目录 `start-input-lab.cmd`，从首页进入「会话工作台」，或打开 http://127.0.0.1:4185/session.html 。安装方式仍见 [RUN.md](RUN.md)，本轮没有增加依赖。

## 五分钟验收

1. 在「拍一段节奏」中载入示例，点击「识别节拍」，再点击「加入当前会话」。也可录制四下定速拍，接着拍完整一小节。
2. 切到「哼一条旋律」，载入示例或录一段 3–8 秒的单人哼唱；转换后比较原始识别和连贯哼唱，选择需要的版本，再加入会话。
3. 速度来源选择「使用已加入的节拍速度」。合成五音示例可手动选 C 大调。实际哼唱若不确定调性，先保留「旋律 + 鼓点」。
4. 检查哼唱录音第 0 拍的秒数、放置位置，确认对齐后生成。默认两个数均为 0：哼唱录音零点放在节拍正式小节的零点，前导休止保留。两段独立录音不能仅凭文件零点推断它们已同步。
5. 回听旋律和伴奏，点击「鼓更有力」，比较两版。再关闭、恢复贝斯，检查主旋律与速度保持。每次成功生成沿用上次成功的声部设置。
6. 试用文字「鼓更有力，速度不变」；再试「鼓更有力，变成一只猫」。第二句应明确不执行，已有结果仍可下载。
7. 修改 BPM 或偏移，旧结果应标为历史版本；重新生成。下载需要的 WAV、MIDI、记录 JSON 和两个输入页中的原录音。
8. 点击「新建会话」会清空会话素材、设置和结果，但不清除两个输入页中尚未下载的原录音，可再次加入。关闭/刷新整个页面会失去原录音；没有自动保存私人音频。

## 设置的含义

- 速度来源：默认 100 BPM、手动 60–180 BPM、已加入节拍的速度。自由哼唱不自动估速；选择节拍速度不会将哼唱拉到网格。
- 调性：用户明确选择的大调/自然小调。现有规则和声按该调性编排，不是逐音自动配和弦；遇到色彩音、转调或复杂旋律，仍可能不合适。
- 调性候选：复用现有音级时长直方图与大小调 profile 相关度算法。短于 8 个音、总发声短于 4 秒、相关度低于 0.7 或领先差低于 0.1，均标为证据不足/有歧义。这些是保守的工程启发式，不是经过校准的概率。少于三种音级或完全均匀的音级直方图不提供候选。任何候选都必须手动采用。
- 未确定调性：保持完整旋律，只配无固定音高的鼓；贝斯与键盘关闭。重新选择调性后默认重新启用贝斯和键盘，力度和密度沿用会话设置。随后仍可关闭贝斯。
- 对齐公式：`输出秒数 = 原录音音符秒数 - 哼唱录音第0拍秒数 + 放置拍数 × 60/BPM`。音符时长不变。若设置的录音起点会截掉已有音符，则拒绝，不自动删音。
- 原录音的尾部休止也计入映射后的片段长度，再向上补齐完整小节；最多 16 小节。WAV 和 MIDI 均保留完整片段结束位置。合成器释放尾音可能使 WAV 略长。
- 节拍素材只使用已识别的一小节骨架；目标会话速度决定它的演奏速度。每段最多 16 小节，最长输入仍受原输入页限制。
- 控件「伴奏简单一点」减少伴奏起音组；不删旋律音符。「鼓更有力」逐步提高鼓力度，达到上限后不会继续增强。

## 本轮实际修复

- 浏览器返回缓存页面时，仍显示的录音 URL 已被释放，导致不能回听；现在缓存页面保留媒体资源。
- 离开页面后旧麦克风权限才返回，会干扰新的录音申请；现在检查捕获代次，旧结果只释放自己的音轨，不解锁新申请。
- 规则同时接受「鼓更有力，鼓保持」；现在具名声部的保持要求进入 preserve 约束，冲突整句不执行。
- 新草稿即使暂时填写无效，也取消旧草稿正在生成的结果，避免先前操作迟到后修改音乐状态。
- 丢失成功响应后重试，使用同一请求 ID 取回结果，不重复叠加力度/密度修改。
- 历史结果有明确文字标记，手机宽度下输入页按内容高度显示完整操作区。
- 页面返回后，旧识别/解码任务不能恢复已替换的录音或音符。哼唱转换保留自己的输入快照，取消任务不会影响新任务的控件；模型推理串行执行，避免 TensorFlow 资源作用域交叉。
- 组合输入后的「鼓保持」「节奏保持」「主旋律保持」按原素材检查，不再与临时默认节奏比较；鼓力度变化可以同时保留拍点。

本轮未再修改哼唱连续性阈值。重新验证持续音、同音重复、短音、换音、休止，并增加固定轻声音量及噪声对照；优化版七组均保留预期音序，最大匹配边界误差约 58.4 ms。详见 [humming-20261103.json](humming-20261103.json)。合成谐波音频、单一音量/噪声配置不能代表真人识别准确率。

## 状态和请求语义

入口代码：`web/session.js`、`src/jammate/web_session.py`。输入页通过同源 iframe 消息显式加入原始 InputEvent；父页只接受自己的两个子窗口。没有将录音本身加入消息或上传云端。

每次生成是同一段音乐的修订：从第 0 小节重新导出，而不是推进声卡的实时播放位置。服务使用上次成功的 JamState 创建候选 StateManager，设置用户明确选择的速度/调性，替换当前素材目录，以 RuleAgent/BandPlan 编排，再由既有 Runtime 执行。新素材在此修订中的 capture 会话时间为未知，原始事件和原录音时间完整保留在导出记录的 inputs；对齐信息单独保存，不伪造两段录音的共同采集时钟。

候选只有在执行成功、草稿版本仍有效且会话未关闭时，才替换正式 StateManager。失败或被替换的候选不会将力度/密度变化提交。时间映射通过 `StateManager.ingest(..., placements={event_id: {beat_origin_s, placement_beats}})` 和已有转换器执行，不改写原始输入音符。

本机 API：POST `/api/session/create`、`/draft`、`/render`、`/close`。draft 包含 inputs（humming/rhythm）和 settings（tempo_source、bpm、key、melody_origin_s、placement_beats、alignment_confirmed）；render 使用 session_id、revision、request_id 和可选 text。冲突返回 409，无效输入或不支持的要求返回 400。

网页只接本地规则，范围限保持输入旋律和调整伴奏。变奏、主动创作、通过文字改 BPM/调性和停播不走此页面的文字入口；分别使用已有独立 Agent 演示或页面设置/播放按钮。未知/矛盾文本不会被当作成功。真实 LLM 没有在本轮调用，既有 LLM 路径的模拟测试属于自动回归的一部分。

最多 8 个会话，空闲 2 小时过期，每会话最多 64 次成功生成；服务只缓存最近两次媒体结果，但保留本会话已成功请求的身份，旧请求不能重复应用。网页保留最近两版用于比较；关闭或刷新页面会关闭该会话。无数据库持久化、服务重启恢复或跨标签共享会话保证。

## 重放下载记录

记录 JSON 包含原始输入、设置、指令、生成前状态、计划与成功后状态。可重放此前累积的鼓力度和密度调整，选择一个尚不存在的输出目录：

```powershell
.\.venv\Scripts\python.exe examples/replay_web_session.py '下载的记录.json' --out tmp/my-replay
```

默认使用内置合成器；同时传 `--fluidsynth <exe>` 和 `--soundfont <sf2>` 可使用相同音源。音源变化会改变音色，音符事件仍可核对。脚本不覆盖已存在的输出目录，也不启动真实 LLM。

```powershell
node tests/input-async-browser.mjs
node tests/input-lifecycle.mjs
node tests/input-browser.mjs
node tests/session-browser.mjs

```

浏览器测试实际运行 Basic Pitch、节拍提取、规则 Agent 和 FluidSynth，检查 WAV 与下载 MIDI。故障场景通过拦截响应、模拟权限和虚拟麦克风构造；不会请求真实麦克风。用于调性/时间测试的已知音符不是识别准确率基准。

## 需要你真人验收的部分

工程验收不等同真人听感认可。仍需用实际麦克风和真人声音检查：持续音/重复音、轻声短音、带气声或滑音、房间噪声、所选调性下和弦是否合适、旋律与节奏的对齐是否符合本人的意图，以及真实设备延迟。本轮未声称实现边录边演奏、自动跟随渐快渐慢、真人识别准确率或现场合奏。
