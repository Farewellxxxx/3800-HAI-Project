# InputEvent to MRT2 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans task by task. User approved continuous local implementation without further intermediate confirmation.

**Goal:** Connect the existing three-page input demo through shared contracts to real MRT2 preview and browser audio.

**Architecture:** Keep model/perception code and the team's Harness. Extend input_band.render_clip with shared backend selection, route audio events through the workspace worker, and expose event/state/plan/receipt trace. Text keeps its existing stateful service and exports the exact accepted event.

**Tech Stack:** Python 3.12, JSON Schema, existing JavaScript/Basic Pitch, pytest/Node/Playwright, official magenta-rt 2.0.3 JAX under WSL.

**Spec:** ../specs/2026-11-14-input-mrt2.md

## Global Constraints
- Existing three inputs; no Start Jam, automatic routing or ASR UI.
- Public contracts remain InputEvent / JamState / BandPlan.
- Keep original text, unknown confidence, raw input evidence and existing user files.
- MRT2 preview must not commit unverified musical state.
- Local branch only; test doubles are separately labelled.

## Review Focus
- Downloaded event differs from the event actually used to generate audio.
- Failed or superseded generations leave stale playable audio or replay state changes.
- Empty/low-confidence perception creates unrelated music instead of a clear rejection.
- Exact text whitespace is lost, or typed text is falsely labelled ASR.
- GPU/process failures block every subsequent request or silently select another renderer.
